(The reader _read_claude_monitor_session_id documents that this writer does not yet exist and the leg fails closed until it does -- so this item is genuinely unlanded.)
2. NON-TERMINAL SKIP (replay-safe) -- in pipeline_agent_pager.py, make the transient monitor skip non-terminal and durable across restart, keyed explicitly on the constant CLAUDE_SKIP_REASON_MONITOR_UNSET.
   - EXPLICIT FAMILY DECISION (resolves the reviewer's missing-vs-malformed ambiguity): the inherited reader _read_claude_monitor_session_id collapses missing-file, OSError, non-UTF-8, empty, whitespace-only, and internal-whitespace into the SINGLE skip_reason value CLAUDE_SKIP_REASON_MONITOR_UNSET ("claude_monitor_session_id_unset_or_malformed"). There is no separate "missing-only" reason. This wave makes that WHOLE unset-or-malformed family retryable rather than splitting missing from malformed -- splitting would require re-designing the inherited monitor reader, which Constraints forbid, and every member of the family clears once the Work-item-1 writer atomically lands a clean id, so all are genuinely transient.
   - (a) LIVE PATH -- in _dispatch_pending_locked, the branch that currently parks a claude skip in skipped_targets and appends a skip receipt: WHEN skip_reason == CLAUDE_SKIP_REASON_MONITOR_UNSET, do NOT add the target to skipped_targets (so _refresh_pending_targets leaves it in pending_targets, retryable on a later dispatch once the monitor file appears) AND do NOT call _append_skip_receipt for it (write no durable terminal trace).
   - (b) REPLAY PATH -- in _reconcile_delivery_state, the skip-receipt rebuild loop over _load_skip_receipts: do NOT rebuild a skipped_targets entry from any skip receipt whose skip_reason == CLAUDE_SKIP_REASON_MONITOR_UNSET (leave the target pending). This is the authoritative replay-safety guard: it keeps the target retryable across restart even if a transient skip receipt was written by an older build, closing the re-terminalize-on-rebuild hole the reviewer flagged.
   - (c) TERMINAL SKIPS UNCHANGED -- CLAUDE_SKIP_REASON_MONITOR_EQUALS_LIVE and any other/future skip reason keep current behavior (parked in skipped_targets + durable skip receipt). Re-evaluating EQUALS_LIVE retryability is deferred to the same follow-up that flips route=both; under route=codex the claude leg is not dispatched, so no live skip fires this wave.
3. ROUTE STAYS CODEX -- in `mu/tools/executors/executor_config.json`, the default route must be codex; the flip to both is deferred to a follow-up wave once a monitor is actually running.
4. REGRESSION TESTS -- add tests in `mu/tests/tools/test_pipeline_agent_pager.py` proving:
   - (a) with RCX_CLAUDE_MONITOR=1 the writer produces claude_monitor_session_id, and without it the orchestrator_session_id behavior is unchanged;
   - (b) a CLAUDE_SKIP_REASON_MONITOR_UNSET skip is left in pending_targets (NOT parked in skipped_targets) and writes NO skip receipt -- exercised across the family (at least the missing-file case and one malformed case, e.g. whitespace-only) so the test proves the whole family is retryable, not just "missing";
   - (c) REPLAY-SAFETY: after such a transient skip, a state rebuild via _reconcile_delivery_state (fresh state + replayed receipts) leaves the target in pending_targets and NOT in skipped_targets -- including the case where a CLAUDE_SKIP_REASON_MONITOR_UNSET skip receipt already exists on disk (it must NOT re-terminalize the target on rebuild);
   - (d) a genuinely-terminal skip (CLAUDE_SKIP_REASON_MONITOR_EQUALS_LIVE) is still parked in skipped_targets with a durable skip receipt (unchanged);
   - (e) the default route is codex.
