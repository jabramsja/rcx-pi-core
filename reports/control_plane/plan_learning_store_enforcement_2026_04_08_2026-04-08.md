## 1. Scope

Single bounded item: Learning Store (PIPELINE-RECOVERY item 5).

**Item A — Learning Store:**
Add the learning store to `recovery_gate.py` per the two-tier architecture in PipelineRecovery.v0.md (lines 160-174). Tier A (ephemeral recovery log, per-worktree) already exists. This wave implements Tier B: `learned_patterns.json` — a persistent store of promoted/demoted patterns that survives worktree cleanup. `observe_outcome()` records recovery results, promotes/demotes patterns, and merge-syncs to the main repo root. `check_learned_patterns()` provides pre-classification override in `attempt_recovery()`.

Design: `mu/docs/agents/PipelineRecovery.v0.md` (Learning Store section, lines 156-251).

**Persistence model:** `learned_patterns.json` is Tier B persistent state per the design doc (lines 169-173). It is NOT ephemeral per-worktree state. Persistence is achieved via merge-on-sync: on any promotion or demotion event, `_save_learning_store()` writes to both the worktree path (`{repo_root}/.agent_bus/recovery/learned_patterns.json`) and the main repo root (derived via `git rev-parse --path-format=absolute --git-common-dir`), using a merge strategy for the main repo write to prevent data loss from concurrent worktrees. On load, `_load_learning_store()` reads BOTH the worktree copy and the main repo copy (if in a linked worktree), merging them so patterns from other worktrees are visible on every load — not just on first run. The merge function `_merge_stores(base, incoming) -> merged` implements the union merge strategy from design doc lines 250-251 — all `pattern_id` keys from both copies are unioned; when the same `pattern_id` exists in both, scalar fields are taken from the record with higher `success_count` (ties broken by more recent `updated_at`), but `distinct_wave_ids` is always set-unioned from both copies so wave evidence is never lost across worktrees (see work item 3 for the complete per-field merge rule). This is applied at both load and save time. The main-repo save path is serialized via `fcntl.flock(LOCK_EX)` on a lockfile (`{LEARNED_PATTERNS_FILE}.lock`) adjacent to `learned_patterns.json`, preventing the TOCTOU race where two concurrent worktrees read the same main-repo snapshot and the later writer drops the earlier writer's newly added patterns. The lock is held for the duration of the read-merge-write cycle and released on close. If the lock cannot be acquired within `LOCK_TIMEOUT_S` (5 seconds), the main-repo sync is deferred: the worktree copy is still written, and the `(repo_root, store)` pair is appended to `_pending_main_repo_syncs` for retry on the next promotion/demotion event or — as a last resort — at process exit via `_flush_pending_syncs()` (see below). All file writes (both worktree and main repo) use atomic temp-file-plus-`os.rename()` — write to `{path}.tmp`, then `os.rename('{path}.tmp', '{path}')` — so a crash or interruption mid-write cannot produce a truncated JSON file. What is deferred to PARALLEL-PIPELINE: automated worktree lifecycle hooks in the dispatcher (copy-on-create / sync-on-teardown per design doc lines 247, 250). Without those hooks, merge occurs when recovery events trigger load/save, plus the `atexit`-registered `_flush_pending_syncs()` as a last-resort sync at process exit (blocking lock, no timeout — throughput irrelevant at shutdown). Since the pipeline executor process exits before the dispatcher tears down its worktree, the worktree data is still accessible at flush time, satisfying the design doc's Tier B contract (line 172: "synced to main repo before worktree teardown"). With the merge logic, file-lock serialization, and atexit flush in place, no patterns are lost from lock timeouts or worktree teardown.

**Fail-closed degradation:** The learning store is a best-effort optimization layer, not a load-bearing dependency. If the persistent store is corrupt, truncated, or malformed, the system must degrade to the existing static classifier — never crash. Specifically: (a) `_load_learning_store()` wraps all JSON decode and schema validation in `try/except (json.JSONDecodeError, ValueError, KeyError, OSError)` — any error returns an empty store `{"patterns": {}, "metadata": {...}}` and logs a warning; (b) `check_learned_patterns()` wraps its entire body in `try/except Exception` — any error returns `None` (fail-closed to static classifier) and logs a warning; (c) `_save_learning_store()` wraps writes in `try/except OSError` — a failed write logs a warning but does not propagate to `attempt_recovery()`. The learning store can never become a crash path for `attempt_recovery()`.

### Key API context (code truth at HEAD)

The learning store integrates into the existing recovery flow, which currently works as follows:

- `classify_failure(result: dict) -> FailureClass` (line 93) — pure classifier. Takes a result dict, returns a `FailureClass` enum. Has NO `repo_root` parameter and makes no filesystem calls.
- `tier_for(fc: FailureClass) -> int` (line 84) — static lookup from `_TIER_MAP` dict (lines 64-75). Maps each `FailureClass` to a tier (1-4).
- `attempt_recovery(repo_root, result, wave_id)` (line 1719) — entry point. Calls `fc = classify_failure(result)` (line 1727), then `tier = tier_for(fc)` (line 1728), then dispatches to `_TIER1_FIXES.get(fc)` (line 1842) or `_TIER2_FIXES.get(fc)` (line 1804) based on the tier.
- `_log_tier3_attempt(repo_root, wave_id, step, failure_class, iteration, action, outcome, duration_s, detail, invocation_id)` (line 982) — per-iteration logger for Tier 3 recovery loop. Has NO `result` dict parameter — only individual fields. NOT a valid observation site.

The learning store override layer is inserted into `attempt_recovery()` BEFORE the `classify_failure()` call, because:
1. `classify_failure()` is a pure dict-inspection function with no `repo_root` parameter — adding one would break its pure-classifier contract and require threading `repo_root` through call sites that currently don't need it.
2. `attempt_recovery()` already has `repo_root` (line 1720) and is the only caller that routes to fix dispatch, so the override is self-contained.
3. The learning store returns both `failure_class` AND `promoted_tier` (since promotion changes the tier, not just the class), and `attempt_recovery()` is where both values are consumed.

3. Implement `_merge_stores(base, incoming) -> dict` — pure-function union merge per design doc line 251
   - Takes two store dicts (each with `{"patterns": {...}, "metadata": {...}}`).
   - Returns a new store whose `patterns` dict is the union of both inputs' `pattern_id` keys.
   - **Conflict resolution (same `pattern_id` in both):** per-field merge, NOT record-level replacement. Scalar fields (`success_count`, `failure_count`, `demotion_count`, `promoted_tier`, `permanently_locked`, `fingerprint`, `failure_class`, `action`, `step`, `environment_tags`, `updated_at`, `last_success`) are taken from the record with higher `success_count` (ties broken by more recent `updated_at` ISO timestamp). **`distinct_wave_ids` merge is environment-aware:** if both records have the **same** `environment_tags` (or either has empty tags — backwards compatibility), `distinct_wave_ids` is set-unioned — `sorted(set(base_record["distinct_wave_ids"]) | set(incoming_record["distinct_wave_ids"]))` — so same-environment wave evidence from different worktrees is preserved, maintaining the two-wave promotion guard (design doc lines 227-228, 303). If the two records have **different** `environment_tags`, `distinct_wave_ids` is taken from the winning record (higher `success_count`) only — no cross-environment union. This prevents mixed-environment successes from jointly satisfying the promotion gate through the merge path: a pattern that saw wave A on linux (worktree 1) and wave B on darwin (worktree 2) must NOT merge to `["wave_A", "wave_B"]`, because those waves are from different environments and the design doc lifecycle diagram (lines 210-214) requires counter reset on environment change.
   - Patterns present in only one input are included unconditionally.
   - `metadata` uses the more recent `last_modified` timestamp.
   - This is the design doc's "merge, not overwrite" contract (line 250-251). It is applied at both load and save time to prevent data loss across concurrent worktrees.

4. Implement `_load_learning_store(repo_root) -> dict`, `_save_learning_store(repo_root, store)` — read/write `learned_patterns.json` with merge-on-sync persistence
   - **Load:** reads worktree copy at `{repo_root}/{LEARNED_PATTERNS_FILE}` (may not exist). If `repo_root` is a linked worktree, ALSO reads `{main_repo_root}/{LEARNED_PATTERNS_FILE}` (may not exist). Merges the two copies via `_merge_stores()`. Returns `{"patterns": {}, "metadata": {...}}` if neither exists. This ensures patterns learned by other worktrees (synced to main repo) are visible to this worktree on every load — not just on first run.
   - **Fail-closed JSON handling (load):** Each file read is wrapped in `try/except (json.JSONDecodeError, ValueError, KeyError, OSError)`. If a file is truncated, contains invalid JSON, or has unexpected schema (missing `"patterns"` dict), that file is treated as empty — logged as a warning, and the load continues with the other copy (or returns empty store if both are bad). Schema check: top-level must be a dict with a `"patterns"` key whose value is a dict; individual pattern records must have `pattern_id` (str), `fingerprint` (str), `failure_class` (str). `environment_tags` (list[str]) defaults to `[]` if absent (backwards compatibility — pre-environment patterns are treated as universal by `_environment_matches()`). `distinct_wave_ids` (list[str]) defaults to `[]` if absent (backwards compatibility — pre-wave-history patterns start with no wave evidence and must earn promotion from scratch). Records that fail validation are skipped (not loaded), not fatal.
   - **Save:** writes to `{repo_root}/{LEARNED_PATTERNS_FILE}` (worktree copy) via atomic temp-file-plus-`os.rename()`. If `repo_root` is a linked worktree, syncs to main repo via a lock-serialized read-merge-write:
     1. Acquire `fcntl.flock(LOCK_EX)` on `{main_repo_root}/{LEARNED_PATTERNS_FILE}.lock` (create if absent). If lock not acquired within `LOCK_TIMEOUT_S` (5s, via `signal.alarm` or non-blocking retry loop), defer main-repo sync: log a warning, append `(repo_root, store)` to `_pending_main_repo_syncs`, and return (worktree copy is already written).      2. While holding lock: read `{main_repo_root}/{LEARNED_PATTERNS_FILE}` (may not exist or may be corrupt — same fail-closed handling as load), merge with worktree store via `_merge_stores()`, write merged result to `{main_repo_root}/{LEARNED_PATTERNS_FILE}.tmp`, then `os.rename()` to `{main_repo_root}/{LEARNED_PATTERNS_FILE}`.
     3. Release lock (close lockfile fd).
     4. On successful main-repo sync, remove any matching entry from `_pending_main_repo_syncs` (the normal-path sync fulfilled the deferred obligation).
     This serialization eliminates the TOCTOU race: two worktrees cannot interleave their read-merge-write to the main repo copy. The atomic rename prevents partial writes from corrupting the store.
   - **Fail-closed write handling:** The entire save (both worktree and main-repo paths) is wrapped in `try/except OSError`. A failed write logs a warning but does not propagate to `observe_outcome()` or `attempt_recovery()`. Creates `.agent_bus/recovery/` directories as needed via `os.makedirs(exist_ok=True)`.

6. Implement `check_learned_patterns(repo_root, result: dict) -> Optional[LearnedMatch]` — step-scoped, environment-scoped, extracted-signal fingerprint pre-classification override
   - Takes the raw result dict (same input as `classify_failure()`), NOT a pre-computed `failure_class`
   - Computes the bounded match target: `lookup_signal = _normalize_fingerprint(_extract_classifier_signal(result)[:80])` — the FIRST 80 chars of the classifier's extracted signal, normalized. This is the match surface per design doc line 302: "fingerprints are matched against the FIRST 80 chars of the classifier's extracted signal, not raw stderr." The `_extract_classifier_signal()` helper replicates the classifier's signal extraction (JSON parsing, embedded reason extraction, combined_text construction) without performing classification, producing the same processed signal that `classify_failure()` inspects. Truncating to 80 chars caps the match surface, preventing long stderr tails (which may contain unrelated output from prior commands) from triggering false matches.
   - Iterates promoted (non-expired, not permanently locked) patterns; for each, checks ALL THREE conditions: (a) the pattern's stored `step` field matches `result.get("step", "")`, (b) the pattern's stored normalized `fingerprint` is a substring of `lookup_signal` (the first 80 chars of the extracted signal, not raw stderr+stdout), AND (c) `_environment_matches(pattern["environment_tags"])` returns `True` (per design doc line 320)
   - On match (all three conditions satisfied), returns a `LearnedMatch` NamedTuple: `(failure_class: FailureClass, tier: int, pattern_id: str, action: str)`
   - On no match (or all patterns expired/locked/step-mismatched/environment-mismatched), returns `None` — caller falls through to static classification
   - **Rationale for signature:** `failure_class` is the OUTPUT of classification, not an input. The fingerprint (extracted signal snippet) is the lookup key, available from the raw result before any classification runs.
   - **Misroute prevention (four layers):** (1) Extracted signal, not raw stderr — `_extract_classifier_signal()` applies the same JSON parsing and reason extraction as the classifier, producing a processed signal that strips structural noise; an adversarial stderr message that embeds JSON to confuse the raw text match is neutralized because the extraction logic parses and flattens it the same way the classifier does (design doc line 302). (2) Bounded match surface — only the first 80 chars of the extracted signal are used as the match target, preventing long stderr tails from contributing false matches. (3) Step-scoped matching — a pattern learned at pipeline step X cannot misroute a failure at step Y. (4) Environment-scoped matching — a pattern promoted on one environment cannot auto-apply on a different environment. Combined with the `MIN_FINGERPRINT_LENGTH` enforcement at promotion time (work item 7 — `observe_outcome()`), these four layers eliminate the risk of generic stderr prefixes (e.g., `"Error"`, `"Traceback (most recent call last):"`) silently misrouting unrelated failures through the override path.
   - **Fail-closed wrapper:** The entire function body is wrapped in `try/except Exception` — any error (corrupt store data, unexpected schema, `_load_learning_store()` returning malformed data, `_extract_classifier_signal()` failure, `_environment_tags()` failure, etc.) is logged as a warning and returns `None`. This guarantees fail-closed degradation: if the learning store is broken, `attempt_recovery()` falls through to the existing `classify_failure()` + `tier_for()` path unchanged. The learning store can never become a crash path.

7. Implement `observe_outcome(repo_root, failure_class, action, fingerprint, outcome, wave_id, step, result)` — record outcome with environment tags, check promotion/demotion thresholds

   - Fingerprint is normalized via `_normalize_fingerprint()` before storage and hashing.
   - `pattern_id = sha256(f"{failure_class}:{action}:{step}:{_normalize_fingerprint(fingerprint)[:80]}")[:12]` — note `step` is included in the hash so the same extracted signal at different pipeline steps produces distinct pattern records (per design doc line 201, extended with step scope). Environment is NOT included in the `pattern_id` hash (consistent with design doc line 201) — the same failure at the same step produces the same `pattern_id` regardless of environment, but the `environment_tags` field scopes when the pattern is applied at lookup time.

   - `environment_tags = _environment_tags()` is captured at observation time and stored in the pattern record (per design doc line 196). **Environment-change counter reset (per design doc lifecycle diagram lines 210-214):** On subsequent observations of the same `pattern_id`, if the current `_environment_tags()` differs from the stored `environment_tags` (and the stored tags are not empty — backwards compatibility for pre-environment patterns), the promotion counters are reset before processing: `success_count` is set to 0 and `distinct_wave_ids` is cleared to `[]`. The stored `environment_tags` are then updated to the current environment. This ensures promotion evidence is per-environment: a pattern that accumulated 2 linux successes restarts from 0 when observed on darwin, preventing mixed-environment successes from jointly satisfying the promotion gate. The counter reset is the same semantic as the design doc lifecycle diagram's "different machine" → "Reset counter" and "env change" → "Reset counter" arrows (lines 210-214). Note: `demotion_count` and `permanently_locked` are NOT reset on environment change — demotion history is a safety ratchet that must be global.
   - On `outcome="success"` (after any environment-change reset above): increment `success_count`, append `wave_id` to the pattern record's persisted `distinct_wave_ids` list (deduplicating: `if wave_id not in record["distinct_wave_ids"]: record["distinct_wave_ids"].append(wave_id)`). **Promotion gate:** If `success_count >= 3` AND `len(record["distinct_wave_ids"]) >= 2` AND `len(_normalize_fingerprint(fingerprint)) >= MIN_FINGERPRINT_LENGTH`, promote to Tier 1. Fingerprints shorter than `MIN_FINGERPRINT_LENGTH` (16 chars after normalization) are recorded for statistics but the pattern is NOT eligible for promotion — this is the primary gate preventing generic stderr prefixes from ever reaching the override path in `check_learned_patterns()`. The `distinct_wave_ids` field is persisted in the pattern record (not computed on-the-fly) so that the two-wave promotion guard survives cross-session and cross-worktree merge-on-sync — `_merge_stores()` unions the `distinct_wave_ids` sets from same-environment copies (work item 3), ensuring that same-environment wave evidence from worktree A seeing wave W1 and worktree B seeing wave W2 are both preserved after merge. Cross-environment wave evidence is NOT unioned (see work item 3).
   - On `outcome="failed"` for a promoted pattern: demote (Tier 1 -> Tier 2, Tier 2 -> Tier 3). On each demotion: increment `demotion_count`, reset `failure_count` to 0 (per design doc line 235).
   - **Permanent lock:** If `demotion_count >= DEMOTION_LOCK_THRESHOLD` (3), set `promoted_tier` to 3 and mark as permanently locked (`permanently_locked: true`). A permanently locked pattern is never re-promoted and is skipped by `check_learned_patterns()`.
   - Promotion is idempotent (re-promoting an already-promoted pattern on the same environment updates `last_success` only; re-promoting after an environment change follows the counter-reset path above).
   - Calls `_save_learning_store()` (which merge-syncs to main repo) after any state change.
