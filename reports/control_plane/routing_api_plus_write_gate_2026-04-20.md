## Problem statement

Two structural defects surfaced together on 2026-04-20 during a hand-authored `post_merge_routing.json` launch:

(1) **No mechanical builder API for `post_merge_routing.json`.** The only existing writer is `mu/tools/agents/meta_bridge_supervisor.py:2258 write_post_merge_routing_record()`, which is Codex-invoked (takes LLM output, not kwargs). The analogous pattern is `mu/tools/executors/commit_executor.py:2360 build_commit_handoff()` — a kwargs-based builder with validation. Without an equivalent for routing records, every hand-authored wave launch requires manual JSON copy-paste of `state_sha`, `blocker_report_paths`, `head_sha`, `merge_sha`, `timestamp_utc`, `next_candidates`. Errors this session: omitted `state_sha` caused dispatcher "Routing record has no state_sha" rejection, requiring `--skip-freshness` workaround.

(2) **`artifact-edit-gate.sh` only blocks Edit tool, not Write.** `.claude/settings.json:32 PreToolUse.Edit` registers the hook. No `PreToolUse.Write` registration exists. The hook logic itself is tool-agnostic (reads `.tool_input.file_path` at `.claude/hooks/artifact-edit-gate.sh:39`, which both Edit and Write populate), but without Write-matcher registration the hook never fires on fresh-file writes. Verified by direct observation this session: I wrote `.agent_bus/meta/post_merge_routing.json` via Write tool 4+ times without the hook blocking, even though the target path matches the hook's artifact pattern at `:62 */.agent_bus/*`.

Combined effect: the hook that SHOULD funnel me to the API isn't firing on Write, and the API doesn't exist yet. Founder directive 2026-04-20: "the hook needs to go off for that..we already discussed API's/recovery that would automatically do this."
