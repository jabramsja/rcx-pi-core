The remaining deltas are below.

Make `_set_pager_route` set the committed `pipeline_agent_pager.route` to the single selected orchestrator X (`claude` or `codex`) so `--mode X` yields `_requested_targets(route) == [X]`, while preserving the existing `orchestrator_mode.json` precedence.
2. **Bare/missing-config role fallback derives the selected roles in both directions (regression-only; mechanism already landed).** The fallback already DERIVES `backends`/`bridge_reviewers` from `role_agents` via `apply_role_agents`. Add focused regressions proving `merge_executor_config_overrides` (and `load_config` on a missing `executor_config.json`) materializes implementer+reviewer `backends`/`bridge_reviewers` that match the supplied `role_agents` in BOTH directions (claude and codex), and that the bare-defaults fallback (`merge_executor_config_overrides({})`) carries no stale provider. This must respect the A2 contract: do NOT have `set_roles` edit `DEFAULT_EXECUTOR_CONFIG`/Python (see Constraints). `test_switch_both_directions` already covers the live-file write path; this item adds the fallback/derivation coverage that path does not exercise.

4. **tmux role labels follow live roles after a set_roles change.** Ensure the implementer/reviewer pane labels are sourced from the live `role_agents` (via `configured_role_agents` / display-name lookup) so a `set_roles` change is reflected.
