1. **Define the binary ADD projection as test-local scaffolding** inside `mu/tests/l4_gates/test_structural_numbers_add.py`: construct the bit-recursive ADD-with-carry projection (per `StructuralNumbers.v0.md` §3.3) as Mu projection structures built **in the test itself**, exactly as the foundation gate defines its encode/decode codec locally ("test scaffolding, not runtime code"). 2. **Add the gate assertions (canonical structural equivalence is the governing assertion)**: for each `(a, b)` in a bounded corpus of host integers, encode `a` and `b` as StructuralNumbers binary-positional numerals, apply the **test-local** binary ADD projection through `run_mu` (Python substrate), and assert the result satisfies the `StructuralNumbers.v0.md` §7.3 equivalence obligation -- the `run_mu` ADD result must be (a) a **valid canonical** StructuralNumbers binary-positional numeral (well-formed per the foundation numeral and in its canonical form, e.g. no spurious leading-zero bits) and (b) **structurally/hash-equal** to `encode(a + b)`, using content-addressed/structural equality (the same equality the foundation gate uses for the numeral), proving `structural_add(a,b) ≡ host_to_structural(to_host(a) + to_host(b))`. 4. **Mark the test `@pytest.mark.slow`** -- it drives `run_mu`, which `.claude/rules/test-classification.md` requires be marked slow; keep the corpus lean because each `run_mu` ADD step carries meta-circular cost.
