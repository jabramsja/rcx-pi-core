# Legacy interrupted review recovery: retained limits

This wave implements an explicit native negative-history operation for intact
pre-marker interruptions. Its implementation evidence and exact actual-history
plan are linked from `TASKS.md`. This advisory grants no approval or mutation
authority. The locked packet and its 2026-10-09 tracker note remain governing.

- Planning reads local Git and preservation files without network access or
  source/index/ref writes. Applying requires the explicit plan SHA-256, unchanged
  inputs and source HEAD, a clean source/index, and the canonical admission lock.
  The operation appends an intent and publication seal outside the old attempt;
  a partial record holds. Identical complete replay changes no bytes. A complete
  unsealed intent may finish only through the same explicit pinned operation.
- The independently reviewed preservation-binding digest is caller authority.
  The tool verifies its manifest, snapshot identity, original inventory and
  independently restored bytes/modes. It does not create a snapshot, claim an
  original exit/completion/request identity, or infer why the reviewer stopped.
  The restored copy and provenance must remain readable on subsequent resumes.
- Original and same-content heads remain held. Corrected descendants gain no
  inherited approval. Recovery retains strict current-request review, CI and
  protected-merge admission even if GitHub quota notices disappear. It never
  passes a recovery record to the original terminal-review receipt validator.

  the outer owner must regenerate and inspect the read-only plan from committed
  code, pin that plan's digest, and explicitly apply/verify it. A plan for the
  earlier HEAD cannot be used for a changed source HEAD. The real legacy a705
  attempt remains held until that outer-owned operation; a successful code
  commit is separate from recovery, review clearance and landing.
